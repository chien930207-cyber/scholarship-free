獎學金導航｜免費版上架教學

照順序完成，不用在自己電腦安裝 Python、Docker 或其他開發工具。建議使用電腦操作，方便上傳整個資料夾。

這次只走一條路線：GitHub 存程式與背景工作 → Cloudflare 提供網站、資料庫與 AI → Tavily 搜尋全新公告。

不要啟用 Render、GitHub Pages、Brave，也不要照舊版教學操作。使用個人帳號，不使用公司的既有正式專案。

文件核對日期：2026-09-20。程式已完成本地測試；未在你的帳號上架。第 6、7 步才是真正的線上驗收。

0｜先確認保持免費

準備三個帳號：GitHub、Cloudflare、Tavily，完成各自的 Email 驗證。

GitHub 儲存庫要選 Public；Cloudflare 使用 Workers Free；Tavily 選 Researcher / Free。不購買網域、不啟用 Paid / Pay As You Go、不加值 AI Gateway。若畫面要求付費或綁定信用卡，先停下確認是否選錯方案。

下載完整 ZIP 後解壓縮。等等上傳的是裡面的檔案，不是 ZIP 檔案本身。

GitHub 公開儲存庫標準 Actions 執行器免費 [1]。Tavily 免費方案為每月 1,000 點且不需信用卡 [2]。Cloudflare AI 免費額度是每天 10,000 Neurons，不是 10,000 次分析 [3]。免費條件以帳號實際方案為準。

1｜在 GitHub 建立一個新儲存庫

  1. 登入 GitHub，點右上角 + → New repository。
  2. Repository name 填 scholarship-free。選 Public，勾選 Add a README file，按 Create repository。
  3. 儲存庫左上方分支應該是 main。先保留這個分頁，稍後回來設定金鑰。

公開的是程式和公開獎學金資料。不要上傳個人備份、成績單、證件、真實金鑰或 .env。後面的四個值只能填進 Secrets。

2｜取得 Tavily 免費搜尋金鑰

  1. 開啟 Tavily 後台，確認方案是 Researcher / Free。
  2. 進入 API Keys，複製或建立一支 API key。值通常以 tvly- 開頭。
  3. 這個值等等填入 GitHub Secret TAVILY_API_KEY。不要啟用自動加值或按量付費。

額度用完會停止外部搜尋，現有獎學金資料仍可查看。[2]

3｜取得 Cloudflare 帳號 ID 與部署金鑰

A. 複製 Account ID

登入 Cloudflare，進入你的帳號。點搜尋（或按 Ctrl / Command + K），搜尋 Copy account ID 並複製。也可以在 Workers & Pages → Account Details 找到。[4]

這是 32 碼英數字，不是 Email，也不是 Zone ID。等等填入 CLOUDFLARE_ACCOUNT_ID。

B. 建立只給這個帳號使用的 API Token

  1. 在 Cloudflare 帳號內找 Account API tokens → Create Token。可由頁面搜尋列搜尋 API tokens。
  2. 可先選 Edit Cloudflare Workers 範本，名稱填 scholarship-free-deploy。範本是起點，還要核對下表權限。[5]
  3. 在權限設定中，只選你剛複製 ID 的那個 Account。不選其他工作帳號或所有網域。
產品需要的權限用途
WorkersWorkers Scripts → Edit / Write。以 Edit Cloudflare Workers 範本為起點，保留建立與更新 Worker 的權限，範圍只選自己的 Account。首次建立 Worker、更新程式與排程。以可建立與更新 Worker 的權限為準。[6]
D1新增 Account → D1 → Edit / Write。自動建立資料庫與初始資料。[7]

不需 Zone / DNS 修改權限。不要使用 Global API Key。完成後按 Continue to summary → Create Token，複製金鑰值，稍後填入 CLOUDFLARE_API_TOKEN。

不用自己建立 D1、貼資料庫 ID 或購買網域。部署程式會建立資源；已有 workers.dev 會沿用，沒有時會嘗試建立一個唯一名稱。若帳號尚未完成 Workers 啟用，先在 Workers & Pages 完成免費啟用，再重試部署。

4｜讓網站有權啟動 GitHub 背景工作

這個金鑰只用來啟動此儲存庫的 Actions，不是你的 GitHub 密碼。

  1. GitHub 右上頭像 → Settings → Developer settings → Personal access tokens → Fine-grained tokens。
  2. 按 Generate new token，Token name 填 scholarship-dispatch，Resource owner 選你自己。
  3. Expiration 建議先選 90 天，並自行記下到期日。到期前要更換金鑰，否則即時補查會停止。
  4. Repository access 選 Only select repositories，只勾選你的 scholarship-free。
  5. Repository permissions 只增加 Actions → Read and write。Metadata Read-only 是自動附帶的，不用增加 Contents Write 或全帳號權限。
  6. 按 Generate token並複製值，稍後填入 GH_DISPATCH_TOKEN。[8]

5｜填入四個值，上傳程式並部署

A. 先設定 Secrets

回到你的 scholarship-free 儲存庫（不是個人帳號設定），點 Settings → Secrets and variables → Actions → New repository secret。一次新增一個，總共四個：

Name（必須完全相同）Secret（填入的值）
CLOUDFLARE_ACCOUNT_IDCloudflare 的 32 碼 Account ID
CLOUDFLARE_API_TOKENCloudflare 的部署 API Token 值
TAVILY_API_KEYTavily 以 tvly- 開頭的 API key
GH_DISPATCH_TOKENGitHub 剛產生的 fine-grained token

值不要加引號、Bearer 或變數名稱。每個填好按 Add secret。金鑰不要貼在 README、Issues、HTML 或對話裡。

B. 上傳解壓後的檔案

回到 Code → Add file → Upload files，把解壓後裡面的全部檔案和資料夾拖入，按 Commit changes提交到 main。儲存庫首頁應直接看到 web、worker、scripts、tests、package.json、requirements.txt，不要多包一層資料夾。

也要確認以下兩個檔案存在：.github/workflows/deploy.yml、.github/workflows/collect.yml。

看不到 .github？點這裡補上兩個檔案

在 GitHub 按 Add file → Create new file，檔名填下列完整路徑，貼入對應內容，各自 Commit changes。原本已存在就不要重複建立。

.github/workflows/deploy.yml

.github/workflows/collect.yml

C. 按一次 Deploy

  1. 打開儲存庫 Actions；如出現啟用工作流程的確認畫面，先啟用。
  2. 左邊選 Deploy free website，按 Run workflow，Branch 選 main，再按一次 Run workflow。上傳後若已自動執行，直接等那一次即可。
  3. 等到綠色勾勾，點進該次執行的 Summary。
  4. 找 Website deployed → Open your website下面的網址。這個才是你實際上線的網站，不是電腦裡的 HTML。

完成後會有一個 https://scholarship-free.你的名稱.workers.dev 格式的網址。這裡只是格式示意，不是已建立的連結。程式已自動建立資料庫和中午排程，不用另開一個 Cron 服務。

6｜確認不是只有首頁能開

  1. GitHub Actions → Collect and verify → Run workflow。
  2. Mode 選 verify，按 Run workflow。這一次會真正連線測試，消耗一次搜尋與一次 AI 呼叫。
  3. 回到剛才部署 Summary 的 Setup check 連結，或在網址後加 /check.html。按「重新檢查」。
檢查項目成功代表什麼
Database read / write真正讀取、寫入 D1並讀回驗證。
Live Tavily search真正的搜尋 API 有回應，不只是填了金鑰。
Live Workers AI真正取得 AI 的 JSON 回應。
Live official source至少一個官方網站成功取得內文。
GitHub job dispatch網站能請 GitHub 啟動背景工作。

若 verify 有紅色錯誤，先看下方「排錯」。單一官網擷取受阻不代表整個網站都無法使用，但不能把這一項寫成已成功。

7｜立刻跑一次更新，再測試自己的資料

A. 立即更新資料庫

不用等隔天。在 Actions → Collect and verify → Run workflow，Mode 選 daily。完成後到 /check.html 看實際成功讀取頁數、新增筆數、完成自動條件整理的筆數。新增 0 筆也可能只是沒有新公告，要一起看擷取成功數與錯誤。

之後每天台灣時間 12:00 自動建立更新工作。Cloudflare 主排程與 GitHub 備援排程會使用同日識別碼避免重複更新。免費 Actions 可能排隊或延遲，12:00 不是完成時間保證。[9]

B. 測試使用者流程

  1. 開啟真正的 workers.dev 網站，點大按鈕「填寫我的條件，開始配對」。
  2. 填真實校名、戶籍縣市與鄉鎮區，勾選成績學期。停止輸入後會自動送出補查，也可按搜尋按鈕。
  3. 會先看到既有資料，再顯示等待背景工作、搜尋、讀取附件、整理條件的進度。免費主機啟動和附件處理可能需要數分鐘，不要連續按搜尋。
  4. 填成績、常見資格並按 儲存我的資料。關閉分頁，用同一瀏覽器重開同網址，確認資料仍在。
  5. 將符合或待確認的案件加入清單，檢查文件份數、擇一規定、校內與官方期限。
完成標準：網站可開啟、verify 真實檢查通過、可產生補查工作、公告入庫後重整仍在、個人條件關閉後可還原。不是只看到首頁就算驗收完成。

這份免費版的實際上限

項目程式的保護設定
外部搜尋整站每天最多 30 次基本搜尋，每曆月 900 次，額度共用。一次學校補查最多使用 4 次搜尋。
學校與戶籍補查整站每天最多 12 個新工作；同 IP 每天最多 6 次，每分鐘 3 次。完全相同且完整成功的查詢共用 6 小時快取。
AI 整理每天最多 16 次 AI 呼叫，常規的完整案件會使用兩次呼叫。不等於 16 筆獎學金；Cloudflare 本身的運算額度也可能更早用完。
文件處理單次補查最多 12 頁，每日更新最多 18 頁；每頁 3 份附件。新連結和暫時額度不足的工作會保留待處理。

可處理公開 HTML、文字型 PDF 與 DOCX。掃描、圖片型條件、舊式 .doc、登入後公告、需執行網頁腳本才出現的內容、過長或有衝突的辦法可能仍是「待確認」。程式不會繞過登入、驗證碼或 robots 限制。

不會只因 AI 輸出 JSON 就視為合格：必須有原文證據、條件驗證並通過另一次一致性檢查。機器整理仍可能出錯，送件前仍要核對原公告。「全網搜尋」是不限既有網站，不是保證一筆不漏。

已知所有管道都截止的案件會下架並歸檔，不重複當成新機會。期限未明不會亂猜日期。平時仍需留意檢查頁的失敗紀錄與金鑰到期日。

個人資料與測試範圍

成績、經濟身分、懲處紀錄、申請清單及文件勾選留在瀏覽器比對，不送給搜尋或 AI。補查會使用校名、縣市鄉鎮、學期與公開公告線索；工作紀錄保留最多 24 小時後於下次清理移除，不寫入公開 Actions 參數。帳號提供商仍有其自己的系統紀錄與隱私條款。

儲存是同網址、同瀏覽器的本機儲存，不是跨裝置登入同步。備份檔未加密，不要放到公開儲存庫。

本次在測試環境驗證了排隊、配額、新公告整理與入庫、條件比對、過期下架及介面操作。外部搜尋與 AI 成功回應使用模擬資料；瀏覽器儲存為明確標記的 Storage 模擬測試。引用的真正線上測試要由你執行 verify，本次未幫你開帳、登入或部署。
